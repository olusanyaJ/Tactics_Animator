# Glossary

Current behavior below is based on repository source, tests, configuration, and [decisions](decisions.md). Planned behavior is not a claim that the feature is implemented.

| Term                  | Meaning and project context                                                                                                                                                                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace             | A group of locally linked projects managed together. This pnpm workspace contains Web, Worker, Engine, Schema, Parser, and DB.                                                                                                                                                     |
| Package boundary      | A rule defining ownership and permitted imports between packages. The allowed imports are recorded in decisions; tooling does not enforce every boundary.                                                                                                                          |
| Schema                | Shared data definitions and runtime validation. Currently exports `Point`, `Movement`, and `isMovement`; it checks finite coordinates and a nonblank player ID, not pitch bounds or squad membership. Zod is planned, not the current validator.                                   |
| Parser                | Converts instructions into structured data. Currently calls a supplied synchronous interpreter, validates its returned movement, and checks the player against a supplied squad. Real AI calls and the full action vocabulary are planned.                                         |
| Engine                | Calculates positions from structured movement data. Currently linearly interpolates between two points and rejects invalid progress without mutating the input. Full animation timing and tactical action handling are planned.                                                    |
| Worker                | Processes export work independently of Web. Currently calculates one position through Engine and passes it to a supplied renderer callback. Queue processing and MP4 export are planned.                                                                                           |
| Runtime validation    | Checking actual values while a program executes. `isMovement` checks unknown input; TypeScript types alone do not validate external data at runtime.                                                                                                                               |
| Type guard            | A function whose result narrows a value's TypeScript type. `isMovement(value): value is Movement` combines runtime checks with type narrowing.                                                                                                                                     |
| Interpolation         | Calculating a value between endpoints. Engine uses `from + (to - from) * progress` independently for x and y.                                                                                                                                                                      |
| Progress              | The fraction of a movement completed: finite values from 0 to 1. Zero gives the start, one the destination; invalid values cause a `RangeError`.                                                                                                                                   |
| Callback              | A function supplied to another function for it to call. Current examples include Parser's interpreter, Worker's renderer, and DB's ownership lookup and save callbacks.                                                                                                            |
| Promise               | An object representing eventual completion or failure of an asynchronous operation. DB callbacks return Promises; that does not establish a real database connection or persistence.                                                                                               |
| Test spy              | A function that records calls so tests can assert arguments and call counts. Current tests use Vitest's `vi.fn()` to check rendering and saving, including that forbidden saves never call storage.                                                                                |
| Smoke test            | A focused check that an important path works. Current tests exercise local validation, movement, delegation, permissions, and the Web-to-Engine import; they do not prove a working browser, AI service, database, or video pipeline.                                              |
| CI                    | Continuous integration: automated checks on proposed or merged changes. The existing GitHub Actions workflow runs the `check` job for PRs targeting main and pushes to main. The human reports a failed run followed by a passing run in PR #1; see the verification record below. |
| Required status check | A check GitHub must see succeed before merging under the branch rules. The recorded policy requires the workflow's `check` job. The human reports observing failed CI block merging and passing CI allow merging in PR #1.                                                         |
| Branch protection     | GitHub rules controlling changes to a branch, including PRs, required checks, and force pushes. The main policy is in decisions; human-reported enforcement at PR #1 is recorded below, without guaranteeing unchanged future settings.                                            |
| Pull request          | A proposal to merge one branch into another, with a diff, discussion, and check results. The recorded policy requires a PR for changes to main; approving reviews are optional in the current solo workflow.                                                                       |

Authentication, persistent database access, browser previews, real AI interpretation, an export queue, and video encoding remain planned integrations. Current callback-based behavior can be tested without those services.

The [human-reported PR #1 verification](agent-log.md#human-reported-verification--pr-1) records the failing-test and restored-test results, followed by the reported merge and local main update. The agent did not inspect live GitHub settings. The report describes enforcement at that time; it does not independently verify every protection option or establish that settings remain unchanged afterward.
